# Sources

Citations and reference material for the talk. Sections are linked from [[Intro]] and other outline notes. Accessed 2026-11-02; re-check live before the talk.

## Definitions of AI-assisted coding

- Claude Code documentation, Anthropic. Describes the agentic tool's file, terminal, and tool access that grounds the "three levels" framing in [[Intro#Slide 3. What AI-assisted coding is]]. https://code.claude.com/docs/en/overview and https://code.claude.com/docs/en/setup

## Limits and risks

- Perry, Srivastava, Kumar, and Boneh, "Do Users Write More Insecure Code with AI Assistants?" Stanford, 2022. Found that participants with an AI assistant wrote less secure code yet were more confident it was secure. Supports the caveat in [[Intro#Slide 6. The caveat before we go on]]. Caveat for the talk: the study used OpenAI Codex, an older model, so cite it for the overconfidence effect, not as a measure of current tools. https://arxiv.org/abs/2211.03622
- Data handling: cite Anthropic's Commercial Terms and Privacy Policy for whether and how prompt data is used, alongside the district's FERPA and California SOPIPA obligations, to support the "do not paste student data" rule. Confirm which plan's terms apply before the talk. https://www.anthropic.com/legal/commercial-terms and https://www.anthropic.com/legal/privacy

## Attacker use of AI

- Anthropic Threat Intelligence, "Detecting and countering misuse of AI: September 2026." Documents threat actors using Claude as an orchestrator across the cyber kill chain, including reconnaissance, credential harvesting, and malware development. Supports [[Intro#Slide 5. Why this is a game changer for small teams]] point 3. https://www.anthropic.com/threat-intelligence
- Optional corroboration: the Microsoft and OpenAI joint reporting and the Google Threat Intelligence Group reports on adversary LLM use, if you want a second vendor's view.

## Small-team security staffing

- CoSN, "State of EdTech Leadership" survey. The 2023 report found about one third of districts have a full-time staff member dedicated to cybersecurity, so most do not. Supports the "no dedicated security engineer" framing in [[Intro#Slide 2. Who this is for]]. https://www.cosn.org/edtech-topics/state-of-edtech-leadership/
- Secondary summary of that finding: "Only one-third of districts have a full-time employee dedicated to cybersecurity," K-12 Dive. https://www.k12dive.com/news/one-third-districts-have-cybersecurity-employees/651509/
